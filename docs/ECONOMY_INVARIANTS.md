# 경제 불변식과 검증

게임의 모든 크레딧은 **환전 불가능한 가상 재화**다. 표시 통화(KRW/USD/HKD/EUR)는 시즌 고정 환산율의 **표시 전용**이며 내부 원장 값은 항상 정수 크레딧이다 (`calendar.ts: DISPLAY_RATE`).

| # | 불변식 | 검증 위치 |
|---|---|---|
| 1 | 핸드/스트리트/액션마다 Σ스택 + Σ팟 기여 = 대회 칩 | `checkInvariants` + 엔진 스트레스 12,000핸드(0 위반), 배치 시뮬레이터는 테이블 핸드마다 `violations` 검사 |
| 2 | 대회: 최초 발행 + 재진입/레이트 등록 발행 = 남은 스택 합 | `tests/mttFast.test.ts` (`totalEntries × startStack`) |
| 3 | 캐시: 바이인+탑업 = 테이블 스택 + 퇴장 칩 | 지갑 `verifyWallet`, `tests/economy.test.ts` |
| 4 | 지갑: 초기 + Σ거래 = 잔액, 거래 id 유일, 거래 후 잔액 일치, 음수 불가 | `verifyWallet` (클라이언트·서버 모두 매 연산), DB `CHECK(balance>=0)` |
| 5 | 대회별: Σ상금 = 상금 풀(+오버레이), 바운티·수수료는 별도 | `prizeStructure` 테스트(Σpayouts=pool, 비증가), PKO 바운티 보존 테스트 |
| 6 | 중복 티켓·중복 정산·같은 액션 이중 반영 금지 | DB 유니크 키 + 멱등 연산 (아래) |
| 7 | 표시 통화를 바꿔도 내부 값 동일 | 표시 함수만 환산, 저장은 정수 |

## 정산 규칙 (필수 계약)
- 입장: 지갑 차감 + 대회 엔트리 기록 **한 배치(원자)**. 같은 `sid` 재요청은 같은 결과(차감 1회).
- 탈락 확정 즉시 순위로 상금 산출·지급. ITM 탈락자가 우승자 결정을 기다리지 않는다. 우승 시 1등 상금 지급 후 완료 화면.
- 멱등 키: 거래 `prize:{sid}` / `bounty:{sid}` / 입장 `entry:{sid}:1` / 재진입 `reentry:{sid}:{n}` / 캐시 `cash-buyin:{sid}` / 정기 지급 `daily:{KST일자}`; 티켓 `tk:{sid}`(+UNIQUE `source_entry`); 랭킹 `rr:{instance}:{human}:{rules}`.
- **수령 버튼은 지급 트리거가 아니다.** 결과 화면은 서버 확정 후에만 「지급 완료」를 표시하고, 실패 시 「정산 오류 — 지급 완료 아님」+ 재시도(멱등)를 보여 준다.
- 안전 모드: 원장 검산 실패 시 서버는 `423 RECONCILIATION_REQUIRED`, 클라이언트는 새 경기를 막고 알린다. 조용한 재계산 없음.

## 정기 무료 크레딧
KST 달력일 기준 하루 1회(`daily:{YYYY-MM-DD}`), 보유 자산(지갑+테이블)이 30,000 미만일 때 상한까지 채워 최대 3,000. 무료 발행분이며 상금 풀 원천이 아니고 랭킹 점수와 무관. 다중 탭/동시 요청 테스트 통과(1회만).

## 회계 감사 화면
지갑 화면: 거래별 변경 전/후 잔액·유형·거래 id(멱등 키)·연관 경기 + 「원장 검산」 결과. 분석실 > 경제 감사: 원장 상금 합계 = 계정 returned 합계 = 대회 전적 합계 비교(불일치 시 legacy/unverified 표시, 보정하지 않음).
